8 canaux/jour, T3 empile (24 entrees), 123 977 parametres, epoque fixe 4,

2. Comparaison demonstrative
---------------------------
Studio propose maintenant deux modes : Prevision individuelle et Comparaison
appariee. Le second reutilise le composant de comparaison existant, egalement
conserve dans Comparaison des modeles. Pas de seconde implementation scientifique.

Sont affiches : les trois observations communes J-2/J-1/J, les predictions de
C8/NEWPOS2/NEWPOS4, les nouveaux pixels, le feu global et les probabilites.
La verite J+1 est une requete distincte, uniquement apres action explicite.
Le tableau ajoute rappel, Dice, precision, TP, FP et FN par modele apres
revelation. Ces nombres sont calcules depuis les grilles de la scene, jamais
depuis les scores agreges. Leur export JSON accompagne les trois predictions.

Le code refuse toute difference d'evenement, date J/cible, contexte, forme,
pas, CRS/affine, observation J ou masque de validite entre modeles.
Le cadrage est commun, fonde sur J et les predictions ; il ne change pas avec
la verite. Les observations suivent aussi le choix grille complete/zone active.
Un changement de scene efface predictions, verite et erreurs ; les requetes
obsoletees sont annulees. Une navigation hors page n'enchaine plus les calculs.

3. Explications scientifiques
-----------------------------
Comparaison explique directement les quatre experiences :
- C8 : 0,5 BCE ponderee (positifs x10) + 0,5 Dice.
- NEWPOS2 : termes BCE des nouveaux positifs multiplies par 2 ; poids effectif
  20 pour ceux-ci, 10 pour le feu persistant ; terme Dice inchange.
- NEWPOS4 : facteur 4, poids effectif 40 ; le reste du protocole est commun.
- FIRE13 : changement des entrees, pas une nouvelle famille d'architecture.
Les echecs aux criteres preregistres sont listes depuis scientific_gates des
resultats verifies. Un meilleur rappel peut augmenter les faux positifs et ne
suffit pas a promouvoir une variante. Seul C8 a un test independant 2021.

Methodologie distingue CNN, U-Net et ConvLSTM des noms d'experiences V2.
Le CNN historique et les U-Net ont des resultats attestes dans leurs protocoles.
SpatialCNN et ConvLSTM existent dans le code ; aucun score ConvLSTM n'est
attribue aux comparaisons V2 ni invente dans l'interface.

5. CRISP-DM et traitement des donnees
------------------------------------
Compréhension metier : detection active quotidienne a J+1, limites explicites ;
pas de surface brulee, d'ignition ou d'alerte operationnelle revendiquee.
Compréhension des donnees : 23 bandes TIFF documentees, canaux reellement
utilises distingues ; absence de CRS exploitable dans le compact explicitee.
Preparation : split chronologique et embargo, 318 train / 53 purges / 80 val ;
normalisation ajustee exclusivement sur train ; masques et contexte T3 verifies.
Modelisation : quatre experiences V2 deja entrainees et U-Net historique ;
aucun nouvel entrainement ; architectures seulement implementees distinguees.
Evaluation : panel commun 2020, criteres figes, comparaison appariee ; C8 2021
termine et scelle ; variantes non promues ; parite logicielle CPU documentee.
Deployment : lancement local, dependances figees, quatre modeles CPU qualifies
en comptant le U-Net historique, FIRE13 archive, etats d'erreur/ADATA, exports,
tests et procedure de sauvegarde/livraison. Installation vierge non revendiquee.

Spark/Parquet : un panneau de preuves lit le rapport et les fichiers existants.
Le master est local[2], soit deux threads sur une machine. Cinq agregats Parquet
sont materialises ; leurs chemins, nombres de lignes et SHA-256 sont consultables.
Aucun cluster distribue, streaming ou nouveau job Spark n'est revendique ou lance.
L'API correspondante et ses artefacts sont verifies par le test backend cible.
